## 确认的问题与处理

| 项目 | 发现 | 定制版处理 |
|---|---|---|
| HTTPS 验证 | `UnsafeTrustManager` 接受任意证书，并设置始终通过的全局 `HttpsURLConnection` 主机名校验器；原 APK 有对应调用 | 删除这段实现与初始化，使用正常平台验证。此问题涉及该 Java HTTPS 路径，未把所有 OkHttp 请求也一概认定为绕过验证 |
| 局域网管理 | 原版启动即在 10481 监听；未带认证即可读取设置及日志；CORS 放宽 | 移除服务与 AndroidAsync 依赖，成品无管理路由。停止原版、仅运行定制版时实测端口拒绝连接 |
| APK 上传与更新 | 未鉴权上传可写入固定 APK 缓存并尝试打开系统安装器；原版另有更新下载流程 | 移除上传／自动安装入口及 `REQUEST_INSTALL_PACKAGES`。未把原行为描述成已证实的静默安装或 Shell 远控 |
| 依赖漏洞 | 初次完整运行依赖扫描命中 Guava `33.3.1-android` 的 [CVE-2026-102554](https://github.com/advisories/GHSA-xxph-c9ww-hj94)，涉及恶意 Java 对象反序列化导致内存耗尽 | 对既有传递依赖加版本约束，采用官方修复版 `33.7.2-android`。未在应用自身源码发现外部 Java 对象反序列化入口，不把命中版本直接等同于已证明可远程利用 |
| 备份与来源 | 原版允许应用备份、内置多个第三方源 | 定制版关闭应用备份，初始默认源仅为本仓库固定 Raw 地址，数据与原版分开 |

静态检查未发现直接 `Runtime.exec`、`ProcessBuilder.start`、外部 `DexClassLoader` 调用或所检查的常见统计 SDK 标记。URL 字符串中也有协议命名空间、文档、示例和 Referer 常量，不能把每一个字符串都当成实际外联。

## 验证

- Release 构建和完整 `lintRelease` 通过：0 个错误、57 个警告。仅缩短两处上游超长日志标签以通过旧 Android 兼容性检查，没有屏蔽 lint 错误。
- APK 签名通过，使用独立证书；没有相机、录音、联系人、短信、无障碍或设备管理权限，也没有安装 APK 的权限。
- 最终 79 个准确版本的 Maven 运行依赖逐项查询 [OSV](https://google.github.io/osv.dev/)，本次无命中；见 `osv-runtime.json` 和 `runtime-dependencies.json`。这不覆盖未映射到 Maven 通告的所有原生代码问题。
- 成品字节码不含原管理／上传路由、安装 APK 的 MIME 入口以及全局信任全部证书／主机名的调用；默认源为用户 GitHub 地址。
- 初装定制版已默认获取本仓库清单；修复依赖后覆盖本次测试包，仍解析出 4 个分组、96 个频道。HTTP 播放取得分辨率；HTTPS 的 CGTN 英语显示 1920×1080、活动音轨启动。人工验收回执以 `audit-summary.json` 为准。
- 原版未卸载、未清除数据；仅为隔离测试停止其进程。桌面、央视频、系统、路由和 DNS 未作此任务之外的修改。

## 保留的限制

- 未做完整原生库逆向、全输入模糊测试或长期流量捕获，不能证明“绝对无后门”。FFmpeg JNI 保留上游库，其各 ABI 哈希与原版一致；这不是对其全部代码的安全认证。
- 为兼容现有直播，HTTP 视频和原 HTTP 节目单仍允许使用，存在明文内容被网络中间方修改的风险。大清单及 gzip 节目单加载逻辑也未加入完整的下载／解压后容量硬限制，仍有资源耗尽风险。
- 广州综合在本次最终播放测试返回上游 HTTP 403，未绕过访问拒绝。它不是此次遇到的证书验证异常；不能把旧取流快照当作永久有效保证。
- OSV 未命中不等同于没有漏洞。原版重新打开后仍会带回它原有的管理接口和证书处理方式；实际使用请区分 `LemonIPTV GitHub` 与原版图标。
